# Проблемы и риски текущей архитектуры при росте до 10 СК

## 1. Синхронный fan‑out из `ins-product-aggregator`

- На каждый запрос агрегатор **синхронно** обращается ко всем СК →
    - суммирование задержек,
    - увеличение хвостовых латентностей,
    - рост вероятности таймаута.
- При удвоении количества СК:
    - время ответа возрастает,
    - частота ошибок увеличивается.
- **Каскадные отказы**: медленная или недоступная СК блокирует формирование всего ответа.
- **Отсутствие кэша/реплики** на стороне агрегатора → невозможность быстрого ответа из локальных данных.

---

## 2. Периодические опросы агрегатора

- **core-app**: опрос каждые 15 минут.
- **ins-comp-settlement**: опрос раз в сутки.

**Проблемы:**
- Возникают **спайки нагрузки** (*thundering herd*) по расписанию.
- **Пульсирующий трафик** на внешние API СК из-за синхронного fan‑out в моменты опроса.
- **Дублирующие локальные реплики** (в `core-app` и `ins-comp-settlement`) обновляются в разное время →
    - рассинхронизация данных,
    - расхождения в бизнес-логике.

---

## 3. Суточная выгрузка полисов из `core-app` для `ins-comp-settlement` (REST)

- Передача **тяжёлых payload’ов** → возможны таймауты и повторные запросы → **дубликаты**.
- **Задержка данных до суток** → отсутствие near‑real‑time для урегулирования.
- **Непрозрачные механизмы идемпотентности** → риск некорректной обработки повторных запросов.

---

## 4. Отсутствие явной стратегии деградации и управления отказами

- Нет:
    - изоляции по внешним СК (*bulkheads*),
    - ограничений конкурентности,
    - *circuit breaker*,
    - *rate limiting*,
    - экспоненциального *backoff*.
- Ошибки у одной или нескольких СК напрямую приводят к **ошибкам клиентского запроса**.

---

## 5. Масштабируемость и производительность

- **Блокирующие вызовы** и риск **исчерпания пулов соединений** при росте до 10 СК.
- **Вертикальная масштабируемость агрегатора ограничена** → становится **SPOF** (*Single Point of Failure*).
- **Высокая нагрузка на БД** сервисов из-за периодических полных перечитываний данных.
